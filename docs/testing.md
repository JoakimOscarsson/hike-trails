# Testing And Local CI

Last updated: 2026-04-29

Use this page as the local test matrix before wiring or changing hosted CI. The project intentionally has one fast default test command and one fuller browser-capable command.

## Core Commands

- `npm test`: fast unit coverage for pure runtime helpers, including search normalization, overview colors, trail route-range selection, distance/kayak filters, library loaders, and loader error paths.
- `npm run data:validate`: read-only structural validation for source and generated public data.
- `npm run data:check`: no-write drift check. It copies the project inputs to a temporary directory, runs `npm run data:build` there, and compares generated `public/data/**`, `public/routes/kayaking/**`, and the kayak generated source manifest/readme against the committed files.
- `npm run runtime:probe`: mocked app runtime contract probe for index/detail/overview/facility fetch paths.
- `npm run runtime:cache-probe`: isolated route-geometry cache behavior probe.
- `npm run typecheck`: TypeScript contract check.
- `npm run build`: production Vite build.
- `npm run ci:check`: portable required gate for local work and CI without a guaranteed browser. It runs data validation, generated-data drift, unit tests, runtime probes, typecheck, and production build.
- `npm run ci:check:browser`: browser-enabled gate. It runs `ci:check` plus `runtime:browser-probe`.
- `npm run ui:smoke:artifact`: scripted UI smoke report for CI artifacts; requires Chrome/Chromium.
- `npm run test:all`: full browser-capable local suite. It runs `ci:check:browser` and writes the UI smoke artifact.

## Coverage Map

Important areas currently covered:

- Public data structure, duplicate IDs, enum-like contract values, route path existence, trail-system shard references, SAT section route and connection coverage/geometry contracts, kayak source/runtime counts, and legacy-output rejection through `data:validate`.
- Source-to-generated drift for the data generated by `npm run data:build` through `data:check`.
- Pure app logic that is easy to regress without a browser through `npm test`.
- Runtime fetch path contracts and route geometry cache mechanics through the runtime probes.
- Startup, overview/detail paths, route request budgets, grouped hiking facility filter behavior, accessibility, print polish, and mobile map deferral through the browser probe and UI smoke report.
- TypeScript and production bundling through `typecheck` and `build`.

Known limits:

- `data:check` intentionally verifies the outputs owned by `npm run data:build`; trail-specific remote-source builders such as `data:roslagsleden` still need explicit runs when those builders or their remote inputs change.
- The UI smoke report is behavioral, not pixel-regression testing.
- Filter tests cover representative route/kayak edge cases, not every data record combination.

## Before CI Changes

Run this locally before changing `.github/workflows/ci.yml`:

```bash
npm run test:all
git diff --check
```

If Chrome/Chromium is unavailable locally, run `npm run ci:check` and note that browser-only coverage remains to be verified in a browser-capable environment.
