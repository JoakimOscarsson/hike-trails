## Executive Summary

Round two found several new, useful issues:

1. Error states are weak when index/detail JSON is slow, corrupt, or hung.
2. Route data has endpoint topology problems across adjacent stages and a few material distance mismatches.
3. Search is not accent-insensitive, so ASCII spellings like `sormlandsleden` fail.
4. Facility toggles, preset changes, and trail switching can generate hundreds of uncached route requests.
5. The app does expensive map work while the mobile map is far below the fold.
6. Search has no accessible name.
7. 200% text zoom and print expose additional overflow/clipping problems.
8. Favorites localStorage accepts malformed shapes and preserves unknown IDs.

## Findings

### P1: Facility Toggles Refetch Route GeoJSON

Severity: High

Reproduction:
1. Open the app in the default Roslagsleden route-builder view.
2. Toggle a non-zero facility chip such as `Camping (3)` repeatedly.
3. Watch `/routes/roslagsleden-stage-*.geojson` requests.

Expected:
Marker filtering should use already loaded route geometry and facility data.

Actual:
Every non-zero facility-chip toggle retriggers route data requests for all 10 Roslagsleden stage files.

Evidence:
- 12 `Camping (3)` toggles produced 151 requests.
- 120 requests were route GeoJSON fetches.
- The 10 Roslagsleden route files were fetched 12 times each.
- DOM mutation add/remove count rose from 107 to 1782.
- Control: 12 toggles of zero-count `Transit (0)` produced 0 requests.

Artifacts:
- /tmp/hike-agent-g/stress-results.json
- /tmp/hike-agent-g/focused-results.json

Likely direction:
Keep route geometry in memory and update marker visibility without remounting/refetching the map.

### P1: Preset Changes Generate Massive Sörmlandsleden Request Bursts

Severity: High

Reproduction:
1. Select Sörmlandsleden.
2. Change route presets several times.
3. Watch route/trail-system network requests.

Expected:
Preset changes should reuse loaded data and only load newly needed geometry.

Actual:
Five preset changes generated 977 requests, 940 of which were route/trail-system requests. Individual Sörmlandsleden stage files appeared up to 10 times in the same scenario.

Artifacts:
- /tmp/hike-agent-g/stress-results.json

Likely direction:
Memoize fetched route GeoJSON by path, decouple marker/preset state from route geometry fetches, and avoid full map teardown for simple range changes.

## Passed Checks / Non-Findings

- Rapid repeated route selection settled correctly on the last clicked route.
- Invalid start/end ordering self-corrected.
- Applying a preset after invalid range manipulation recovered the expected range.
- Context route toggling on Sörmlandsleden stage 6 updated and removed consistently.
- No new failures were found for duplicate top-level IDs, missing/malformed HTTP(S) source URLs, bad coordinate order in content records, missing route files on disk, missing route-group section references, preset ranges outside route groups, zero/negative distances, or unusable facility/access coordinates.
- Repeated zero-count chip toggles did not cause network requests.
- Repeated clicks on the same section row did not show unbounded marker/path growth.
- No persistent JS heap leak was confirmed.
- Forced colors/high contrast did not add a new issue beyond already-known map-marker semantics.
- Reduced motion did not show a major new issue.

## Suggested Fix Priority

1. Add route-geometry memoization and stop refetching routes on marker toggles, preset changes, and trail switching.
2. Add explicit loading/error/retry states for index and detail JSON failures.
3. Normalize route geometry direction/endpoints and audit affected stage topology.
4. Make search accent-insensitive and give the search input an accessible name.
5. Delay below-fold mobile map work or make the map reachable earlier.
6. Improve text-zoom and print styles.
7. Harden favorites storage validation.
8. Clean up contrast and duplicate/ambiguous facility labels.
